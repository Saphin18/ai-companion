Companion — UI / UX sample

Three screens drawn with your actual Lamplight tokens and the Fraunces / Figtree scale. Nothing in the app has been changed — this is a proposal to look at. Hit Replay animations to see the motion.

The honest diagnosis first. The palette and the type are genuinely good now — that part is done. What the app is missing is hierarchy and payoff. The landing page tells people what the app is instead of showing them, and the home screen is a greeting plus a text box, so the whole product looks like one feature. Everything below is about using data you already store — moods, goals, journal entries, sessions — to make each screen feel lived-in.

A home for the quote Now that a quote is rare and real, mark it: a 3px accent bar down the bubble edge and the line itself in italics. It reads as a moment rather than decoration — and because the gate only opens roughly once per conversation, this treatment stays special.

Voice notes should look like voice notes A play triangle, a waveform, a duration. Right now a transcript just appears as text and the user loses the fact that they spoke.

Typing indicator Three bouncing dots in an empty companion bubble, shown the moment the request leaves. Groq can take a couple of seconds; without this the app feels broken and people re-send. Highest value / lowest effort item on this page.

Smaller things that add up Day dividers ("Today", "Yesterday"); timestamps only on the last message of a group, not every bubble; bubble max-width 80% so lines stay readable; 7px corner on the tail side and 19px elsewhere so direction reads at a glance.

4. Animation

answer: yes, but only five

You have one animation today (the orb bloom at launch) and it is good. Below are the five worth adding. All are transform and opacity only with useNativeDriver: true — the same constraint Session 23 set, so none of them needs reanimated or a dev build. Anything animating width, height or colour is off the list on purpose.

1. Launch bloom

Already built. Keep it exactly as is. It fills a wait that already existed, so it costs no time.

scale .3→1 · ring ripple · 1500ms
Nice one.

2. Message arrival

Each bubble pops in with a slight overshoot instead of appearing. Sent messages rise from the input, replies fade in from the left.

scale .6→1 + translateY 16→0 · 450ms · spring

3. Typing dots

The one that changes how the app feels most. Show it the instant the request is sent, never after a delay.

3 dots · translateY -5px · 1250ms loop · 160ms stagger
T

4. Mood dot fill

When they log a mood, the dot fills and settles. A small reward for a small action — this is what makes people do it again tomorrow.

scale .4→1.12→1 · 900ms
Pick up where you left off

5. Screen transitions

Home→Chat slides in from the right, back slides out. Gives the app a sense of place instead of hard cuts between screens.

translateX 34→0 + fade · 600ms · ease-out
Just talk

6. Press feedback

Every chip, tile and button dips slightly on touch. Nearly invisible, and its absence is exactly why an app feels dead.

scale 1→.94→1 · 120ms down
DoDon't
Animate transform and opacity only. Animate width, height, colour or shadow — those run on the JS thread and stutter on cheap phones.
Keep everything under 600ms. Feedback under 150ms. Long cinematic intros. They are charming once and infuriating by the fifth launch.
Let motion be interruptible — a tap mid-animation jumps to the end. Block input while something is moving.
Respect AccessibilityInfo.isReduceMotionEnabled() and fall back to a plain fade. Assume everyone wants motion.
If you only do three things: the typing indicator in chat, the continue-where-you-left-off card on home, and the live conversation preview on landing. Those three change how the product reads more than the other nine combined.
