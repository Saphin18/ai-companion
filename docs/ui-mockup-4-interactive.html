1. “This week” — what it is

Seven dots, Monday to today. Each one is that day's mood, and the colour gets stronger with intensity. It is not something you fill in — it fills itself.

ThingWhat it does
How a dot gets filled Automatically. detect_mood() already runs on every message you send and writes the result to mood_logs. You have been collecting this data the whole time — it has just never been shown to anyone.
Colour Opacity by intensity (1–5). Pale = a mild day, solid accent = a strong one. No red/green — this is a memory, not a scorecard.
Tapping a past day Opens a small sheet: what the day felt like and how many times you talked, with a shortcut to that day's chat.
Today's dashed + Means nothing logged yet today. It fills the moment you send your first message. Tapping it just opens the chat.
Why it's worth having It is the one screen element that proves the app is paying attention. Everything else you have to ask for; this just appears.
Cost, honestly. This is the only thing I have proposed that is not free. mood_repository.py has exactly one function — add_mood_log. There is no read, no endpoint, and grep finds no mention of mood anywhere in the frontend. You would need: a list_recent_moods(user_id, days=7) repo function, a GET /moods/week endpoint, and the strip. Maybe an hour of backend, an hour of frontend. Everything else on this screen is free.

2. The chips — what they do

They open a new chat that has already started. The blank text box is the hardest moment in any companion app, and these remove it.

ChipSendsWhy
Just talknothing — opens an empty chat The normal path, kept as the default so the chips never feel compulsory.
Vent“I need to vent about something” Tells the mood detector straight away that this is a low conversation, so the register starts right instead of warming up over three messages.
Overthinking“I can't stop overthinking” Your single most common message, judging by the screenshots you sent me.
Good news“I've got good news” Opens in the playful register. Right now nothing in the app invites a good mood — it is built entirely around bad days.
These are free. ChatsListScreen already takes onStartChatWithMessage(text) and App.tsx already handles it. A chip is four lines of JSX calling a function you wrote in an earlier session.

The nicer version, later: rather than sending visible text, pass a tone_hint on the chat request so the register is set without a fake message appearing in the thread. That needs a backend field — worth doing once the chips prove they get used, not before.

3. Timezone — don't hardcode Nepal, don't remove it

The phone already knows where it is. Group the days on the device and the problem disappears for everyone, everywhere, with no setting.

ApproachVerdictWhy
Hardcode Asia/KathmanduNo Works for you, breaks for every other user, and silently — their days are just wrong by a few hours and they never know why.
Ask the user to pick a timezoneNo A setting that can only ever be wrong. Nobody updates it when they travel.
Drop the featureOverkill The fix is one line.
Group on the deviceYes The server returns raw UTC timestamps; the phone buckets them. JavaScript's Date is already in device-local time. Travel to London and the history re-buckets correctly on landing. This is what WhatsApp and iMessage do.
The whole fix: const localDay = new Date(log.created_at).toDateString();

But verify one response first. This only works if the API returns the UTC marker — 2026-10-16T18:30:00Z or +00:00. Your column is DateTime(timezone=True) so it should. If a naive timestamp (2026-10-16T18:30:00, no Z) ever slips through, JavaScript reads it as local time and every day silently shifts by 5:45 — and only for users outside UTC. Brutal to debug after the fact.

Week starts Monday, as you said — that matches Nepal and Europe. Worth knowing it is Sunday in the US, so if you ever want that right, read it from the device locale rather than hardcoding. The strip above is labelled “Last 7 days” for a different reason: on a Monday morning a Mon–Sun strip shows a single dot and looks broken. Same component either way — your call.
Summary: chips — clickable, free, build them. Mood strip — clickable, genuinely valuable, but roughly two hours of work across both ends. If you only want the free wins, do the chips and the contextual line and leave the mood strip for later.
